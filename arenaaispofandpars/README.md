# arena-api

Типизированный синхронный и асинхронный Python-клиент и CLI для **Arena (`arena.ai`)** с автоматическим подхватом сессии и прокси из браузера, TLS-имперсонацией (`curl_cffi`), **невидимым фоновым браузером** для прохождения reCAPTCHA Enterprise v3 и встроенным аудио-авторешателем капчи **без внешнего `ffmpeg`**.

---

## Возможности

- **Zero-config подхват сессии и прокси**: автоматически читает куки из локального профиля Firefox (включая живую сессию `recovery.jsonlz4` Firefox 136+ и настройки прокси `prefs.js` / системного прокси Windows), профилей Chromium (`rookiepy`), `state/cookies.json` или `ARENA_COOKIE`.
- **Невидимый фоновый режим**: запросы Direct Chat выполняются через настоящий десктопный Chrome / Edge / Chromium со скрытым за пределами экрана окном (`WS_EX_TOOLWINDOW`, без иконки в панели задач, без `Alt+Tab` и без перехвата фокуса).
- **Встроенное авторешение капчи без FFmpeg**: при появлении Cloudflare Turnstile или Google reCAPTCHA v2 челлендж автоматически решается в фоне (декодирование аудио через WebAudio `OfflineAudioContext` + встроенный чистый Python FLAC-кодер).
- **Чистый UTF-8 поток**: корректно декодирует кириллицу и эмодзи из стриминговых ответов `arena.ai` и безопасно выводит текст в консоль Windows (`cp1251` / `cp866` / `utf-8`).
- **Лёгкое ядро**: базовый `import arena_api` зависит только от `httpx[http2]`; тяжёлые зависимости (`playwright`, `curl_cffi`, `rookiepy`, `arena_api._vendor.recaptcha_toolkit`) подгружаются лениво только тогда, когда реально нужны.

## Установка

```bash
# Полная установка со всеми возможностями (рекомендуется)
python -m pip install -e ".[auto]"

# Если на ПК нет установленного Google Chrome или Microsoft Edge:
python -m playwright install chromium
```

Дополнительные профили зависимостей в `pyproject.toml`:
- `.[impersonate]` — отправка HTTP/2 и TLS-отпечатка реального браузера (`curl-cffi`, `httpx-curl-cffi`);
- `.[firefox]` — чтение профилей браузеров через `rookiepy` (для Firefox также есть встроенный lock-safe читатель `cookies.sqlite` + `recovery.jsonlz4`);
- `.[e2e]` / `.[captcha]` / `.[auth-captcha]` / `.[vision]` — браузерное окружение и дополнительные бэкенды капчи;
- `.[dev]` — `pytest`, `mypy`, `pyflakes`.

## Быстрый старт (CLI)

Достаточно один раз быть авторизованным на `https://arena.ai` в своём браузере (например, Firefox) или выполнить `--login`:

```bash
# Отправить запрос и получить потоковый ответ (браузер работает полностью невидимо)
python -m arena_api --prompt "Привет! Чем хорош дебют Гроба?"

# Указать конкретную модель (по умолчанию используется авто-выбор самой свежей модели сайта)
python -m arena_api --model claude-opus-4-6 --prompt "Объясни разницу между TCP и UDP."

# Список доступных моделей
python -m arena_api --models

# Проверить найденную сессию и статус доступа
python -m arena_api --status
arena-api --status

# Показать все проверенные источники кук, прокси и TLS-профиль без сетевых запросов
python -m arena_api --explain

# Диагностика профилей Firefox
python -m arena_api --diagnose

# Разовый ручной вход в окне браузера с сохранением кук в ./state/cookies.json
python -m arena_api --login

# При необходимости показать окно браузера для визуальной отладки
python -m arena_api --show-browser --prompt "Тест с видимым окном"
```

## Тёплый демон: мгновенные повторные ответы

Почти всё время между `arena-api --prompt ...` и первым символом ответа уходит
не на генерацию, а на одинаковую для каждого запроса подготовку: чтение
сессии, запуск браузера, загрузку Direct Chat, прогрев композера и подпись
reCAPTCHA v3. Поэтому одиночный запрос с нуля стоит секунды, даже когда модель
начинает отвечать сразу.

Первый `--prompt` теперь поднимает фоновый демон (`python -m arena_api.warm`),
который держит браузер и вкладку Direct Chat уже загруженными. Все следующие
вызовы CLI подключаются к нему по loopback-сокету и платят только за отправку
промпта:

```bash
arena-api --prompt "Привет!"      # первый вызов: запускает демон (как раньше)
arena-api --prompt "А теперь про TCP?"   # ~десятки миллисекунд до отправки
arena-api --warm-start            # поднять демон заранее (например, из скрипта при входе)
arena-api --warm-status           # где демон, тёплый ли браузер, сколько простаивает
arena-api --warm-profile 3        # где последние 3 промпта потратили время (фазы + метрики)
arena-api --fast-submit --prompt "..."   # отправка по Enter (ещё ~0.2-0.3 с), opt-in
arena-api --warm-stop             # остановить демон и закрыть браузер
```

- После прогрева вкладка Direct Chat **не перезагружается** между запросами:
  ротация `arena-auth-*` и собственные cookie страницы не считаются поводом
  для `page.goto()` (это экономит 1–3 с на каждый повторный промпт).
- Демон слушает только `127.0.0.1`, доступ по случайному токену из файла
  `state/warm-daemon.json` с правами `0600`; в сеть ничего не отдаётся.
- Простаивая `--warm-idle` секунд (по умолчанию 900), он завершается сам и
  закрывает браузер.
- Любая проблема (нет браузера, занятый профиль, устаревший state-файл, сессия
  отклонена) означает прозрачный откат на прежний путь в том же процессе:
  вывод и код возврата остаются прежними.
- Отключить: `--no-warm` для одного запуска или `ARENA_WARM=0` целиком.
  Управление таймаутами: `--warm-idle`, `--warm-timeout`, `ARENA_WARM_IDLE`,
  `ARENA_WARM_TIMEOUT`; свой путь к state-файлу — `--warm-state` /
  `ARENA_WARM_STATE`.

Демон использует тот же `--prompt`/`--model` и те же флаги, что и обычный
запуск: они передаются ему целиком, поэтому семантика опций (прокси, профиль,
канал браузера, решатель капчи) не дублируется.

### Замер: `ARENA_PROFILE=1`

Чтобы увидеть, где на самом деле уходит время, включите профилирование:

```bash
ARENA_PROFILE=1 arena-api --prompt "Привет!"
```

В конце работы в stderr печатается таблица фаз (поиск сессии, запуск браузера,
загрузка страницы, отправка, первый байт). `ARENA_PROFILE=json` выдаёт ту же
информацию одной JSON-строкой — удобно собирать в цикле или в CI. Отсчёт
начинается с момента загрузки профилировщика (несколько миллисекунд после
старта интерпретатора), поэтому «total» — это время работы кода пакета, а не
полное время команды.

Фазы `composer.visible` → `composer.focused` → `prompt.filled` →
`send.dispatched` показывают, сколько заняла сама отправка внутри страницы.

Как читать таймлайн: разница между `first_byte` и `warm.ask.end` — это уже
генерация на стороне Arena (её библиотека не ускоряет), а строки до
`first_byte` — наш оверхед (страница, отправка, сеть). Метрики под запросом
(`answer.chunks`, `answer.longest_gap_ms`) показывают, стрим шёл всё время или
сервер долго молчал.

Если ответ всё ещё медленный, самый быстрый способ понять почему — попросить
у демона таймлайн последних запросов; там видно разделение «браузер/страница/
отправка» против «модель/сеть»:

```bash
arena-api --warm-profile
```

Чтобы измерить выигрыш на своей машине (без «на глазок»), есть готовый
бенчмарк: он N раз запускает один и тот же промпт холодно и через демон и
печатает медианы и коэффициент.

Прогоны идут подряд, без пауз и повторов; сбой одного прогона печатается в
колонке `failed` и не прерывает замер.

```bash
python tools/bench_cli.py --prompt "Ответь одним словом: ок" --runs 3
```

## Использование из Python

### Direct Chat (`arena.ai`, синхронно и потоково)

```python
import sys
from arena_api import AutoOptions, auto_direct_client

with auto_direct_client(
    AutoOptions(), verification_token="auto", prewarm=True
) as client:
    for chunk in client.stream("Привет! Напиши 3 коротких совета по Python."):
        if chunk.delta:
            sys.stdout.write(chunk.delta)
            sys.stdout.flush()
```

`prewarm=True` заранее запускает браузер, устанавливает cookie и загружает
Direct Chat-страницу параллельно с проверкой сессии. В быстром CLI-пути этот
прогрев включён автоматически. По умолчанию (`AutoOptions.fast_model=True`)
клиент автоматически выбирает быструю текстовую модель без долгой фазы
`thinking` (`flash-lite`, `flash`, `haiku`, `mini`), что ускоряет ответы на
порядок; для тяжёлой модели по умолчанию используйте `--no-fast-model`,
`--model max` или `ARENA_FAST_MODEL=0`. Если в `--model` / `model=` передан
готовый UUID модели, клиент отправляет его сразу, без дополнительного
GET-запроса за каталогом моделей; разрешение человекочитаемого имени
по-прежнему использует каталог.

### Асинхронный Direct Chat

```python
import asyncio
from arena_api import AutoOptions, auto_async_direct_client

async def main() -> None:
    async with await auto_async_direct_client(
        AutoOptions(), verification_token="auto", prewarm=True
    ) as client:
        answer = await client.acomplete("Коротко сравни SQLite и PostgreSQL.")
        print(answer)

asyncio.run(main())
```

### Классический Gradio-клиент

Для развёртываний со стандартной очередью Gradio (`/queue/join`) доступен `auto_client()` (и асинхронный `auto_async_client()`):

```python
from arena_api import auto_client

with auto_client() as client:
    print(client.complete("Hello!"))
```

## Claude Code на моделях Arena

Claude Code (и Claude Agent SDK) разговаривают с `api.anthropic.com` по протоколу
Messages API. Библиотека умеет отвечать этим же протоколом на loopback-порту и
отправлять запросы через ваш же Direct Chat — то есть **вместо Claude в оболочке
Claude Code отвечает Arena** (на той модели, к которой у сессии есть доступ).

Если `arena-api` падает с `ModuleNotFoundError: No module named 'arena_api'`,
значит `arena-api.exe` остался от установки, у которой больше нет самого пакета.
Быстро проверить и починить:

```bat
py -m arena_api --version          :: из корня клона работает и без установки
py -m pip install -e ".[auto]"     :: вернуть пакет тому же Python
```

Если `--claude` отвечает «unrecognized arguments», установлена старая сборка —
проверьте, откуда она взялась, и обновите:

```bash
arena-api --version     # версия + путь к установленному пакету + есть ли шим
pip install -U -e ".[auto]"   # из клона репозитория
```

### Одним файлом (Windows)

В репозитории лежит `arena-claude.bat`: он сам поднимает шим на порту, ждёт
готовности, выставляет переменные, запускает `claude` и гасит шим, когда
Claude Code закрывается.

```bat
arena-claude.bat                 :: обычный запуск, порт 8082
arena-claude.bat --resume        :: все аргументы уходят в claude как есть
arena-claude.bat doctor          :: диагностика: пакет, сессия, движок, SSE
arena-claude.bat version         :: какая сборка отвечает и что она умеет
```

Батник сам выбирает сборку: пробует `arena-api`, затем `py -m arena_api`, затем
`python -m arena_api`, и берёт первую, которая сообщает `anthropic shim: yes`
и поддерживает `--session`. Если такой нет — печатает версию найденной и команду
обновления, вместо того чтобы молча висеть. Если шим упал сразу после старта,
он показывает хвост лога (`%TEMP%\arena-claude-<порт>.log`) и запускает
диагностику, не дожидаясь таймаута.

Вывод самого батника — латиницей: `cmd` читает скрипт в кодировке консоли, и
кириллица в нём превращается в мусор. Русские сообщения печатает Python
(`--doctor`), которому кодировка консоли не мешает.

Настройки — переменными перед запуском:

```bat
set ARENA_CLAUDE_PORT=9000
set ARENA_CLAUDE_SESSION=firefox:work
set ARENA_CLAUDE_MODEL=arena-auto
arena-claude.bat
```

Если что-то не работает, начните с `arena-claude.bat doctor` (или
`arena-api --claude --doctor`): он проверяет четыре звена — установленный
пакет, сессию, движок ответа и протокол на loopback — и называет первое
сломанное.

### Вручную

По умолчанию шим берёт **сессию Firefox** (`--session firefox`): это профиль,
который библиотека читает лучше всего, и его куки + TLS-отпечаток уходят в
запросы, то есть Claude Code разговаривает с Arena как уже вошедший пользователь
Firefox. Профиль можно указать явно, а лестницу поиска — вернуть:

```bash
arena-api --claude --session firefox:work   # конкретный профиль
arena-api --claude --profile-root D:\Firefox\Profiles
arena-api --claude --session auto           # обычный порядок: файл -> Firefox -> другие браузеры
arena-api --claude --session storage        # только ./state/cookies.json
```

```bash
# 1. поднять шим (сессия берётся тем же zero-config путём, что и в CLI)
arena-api --claude --port 8082

# 2. в другом терминале — Claude Code на нём
export ANTHROPIC_BASE_URL=http://127.0.0.1:8082
export ANTHROPIC_API_KEY=arena        # значение любое, ключ не проверяется
claude
```

Короткий вариант (та же команда, отдельный entry point):

```bash
arena-claude --port 8082 --model arena-auto
```

### Что реализовано

| Что | Как |
| --- | --- |
| `POST /v1/messages` | Поток (`text/event-stream`: `message_start` / `content_block_*` / `message_delta` / `message_stop` / `ping`) и обычный JSON-ответ. |
| `POST /v1/messages/count_tokens` | Оценка `input_tokens` (≈4 символа на токен), чтобы клиент считал контекст. |
| `GET /v1/models`, `GET /v1/models/{id}` | Список моделей: `--model` плюс всё из `--arena-model`. |
| `system`, история, `tool_use` / `tool_result` | История рендерится в один текстовый транскрипт, результаты инструментов видны модели. |
| `stop_sequences` | Обрезка ответа и `stop_reason: "stop_sequence"`, в том числе на потоке. |
| `usage` | Оценка токенов входа/выхода. |

### Инструменты (tool use)

Arena отвечает обычным текстом, поэтому `tools` из запроса рендерятся в промпт
строгим форматом, а ответ разбирается обратно в блоки `tool_use` со
`stop_reason: "tool_use"`:

```
<tool_call>{"name": "Bash", "arguments": {"command": "ls -la"}}</tool_call>
```

Разбор понимает и `` ```json ``-фенс, и «голый» JSON-объект, но только если в нём
есть поле аргументов — чтобы проза с фигурными скобками не превращалась в вызов.
Текстовые ответы при этом стримятся по дельтам, как обычно; буферизуется только
тот ответ, где реально начал формироваться вызов (иначе нельзя отличить
`<tool_` от текста). Отключить эмуляцию: `--tools off`.

### Движки ответа

- `--engine warm` (по умолчанию) — через тёплый демон: вкладка уже открыта,
  ответ начинается почти сразу; при недоступности демона запрос автоматически
  уходит на `http`;
- `--engine http` — свой `DirectArenaClient` в процессе шима (холодный старт);
- `--engine echo` — возвращает промпт обратно: проверка проводки без сессии и
  браузера (`curl`, тесты, отладка клиента).

Все настройки дублируются переменными окружения: `ARENA_CLAUDE_HOST`,
`ARENA_CLAUDE_PORT`, `ARENA_CLAUDE_ENGINE`, `ARENA_CLAUDE_MODEL`,
`ARENA_CLAUDE_BASE_URL`, `ARENA_CLAUDE_TOOLS`, `ARENA_CLAUDE_MAX_PROMPT_CHARS`,
`ARENA_CLAUDE_SESSION`, `ARENA_CLAUDE_PROFILE`, `ARENA_CLAUDE_PROFILE_ROOT`.

Флаг `--session` есть и у самого CLI (`arena-api --session firefox --prompt ...`,
`--status`, `--explain`): он пропускает лестницу поиска и берёт ровно указанный
источник. Если в нём нет кук — это внятная ошибка, а не тихий откат на другой
браузер. Тёплый демон при этом помнит сессию, с которой запущен: запрос с явно другим
`--session`/`--profile` поднимет свой демон, а не переиспользует чужой. Запрос
без явного источника совместим с любым тёплым демоном — иначе чередование CLI и
шима перезапускало бы браузер на каждом вызове.

### Архив отвеченных чатов

Claude Code открывает новую беседу на каждый запрос, а в сайдбаре Arena они
копились бы сотнями. Поэтому шим **архивирует беседу, как только ответ получен
полностью** (пункт «Архив» в меню беседы).

В `arena-claude.bat` архивация включена **всегда** и отключить её нельзя: батник
сам передаёт `--archive` и выставляет `ARENA_CLAUDE_ARCHIVE=1`, что бы ни лежало
в окружении. Если нужен режим без архивации — запускайте шим напрямую:

```bash
arena-api --claude --no-archive      # оставлять чаты в списке
```

Что гарантирует «всегда»:

- **Флаг едет с каждым запросом**, а не только с аргументами демона: тёплый
  демон мог быть поднят CLI (он по умолчанию не архивирует), и шим
  переиспользует его — архивация всё равно произойдёт.
- **Отложенный архив не теряется.** Если следующий промпт уже ждёт, клик по
  меню не встаёт ему на пути: беседа запоминается по своему id и уходит в архив
  на следующем ходу. Именно из-за потерянных отложенных архивов сайдбар и
  зарастал.
- **Архив по id, а не «по тому, что открыто»**: отложенная беседа находится в
  списке по своей ссылке, поэтому её можно заархивировать, даже когда на экране
  уже другой чат.

На уровне библиотеки это `AutoOptions(archive_after_answer=True)` или флаг
`arena-api --archive-after-answer`: действие выполняется один раз, после того
как поток ответа был разобран целиком, и только для одноразового запроса —
follow-up турну нужен открытый чат. Если меню не нашлось (другая вёрстка),
запрос не падает: в профиле появляется фаза `archive.missed`, а беседа остаётся
в списке должников и будет ещё раз попробована на следующем ходу.

### Почему запрос иногда «долго отправляется»

Несколько вещей выглядели как медленная сеть, хотя задержка была на нашей
стороне:

1. **Перезапуск тёплого демона из-за подписи сессии.** Демон помнит, с каким
   `--session`/`--profile` он поднят. Раньше запрос *без* явного источника
   (а CLI и шим подписывали себя по-разному) считался «чужим», демон
   останавливался и следующий запрос снова проходил холодный старт браузера —
   десятки секунд на пустом месте. Теперь пустая подпись совместима с любым
   тёплым демоном: перезапуск только когда источник указан явно и **отличается**.
2. **Архивация между запросами tool-loop.** Архив кликается после полного
   ответа, а Claude Code тут же присылает следующий турн с результатом
   инструмента. Клик по меню вставал ровно между ними. Теперь шим спрашивает
   `WarmSession`, есть ли уже ждущий запрос, и при очереди **пропускает**
   архивацию (метка `archive.skipped`): чат останется в списке и уйдёт в архив
   на первом же турне без очереди (обычно последнем).
3. **Архивация задерживала конец ответа.** Клик по меню — это 200–600 мс
   работы UI, и они стояли между последним токеном и `message_stop`. Теперь
   архив (а вместе с ним обновление cookies и prefetch страницы) идёт фоном
   сразу после ответа: клиент уже читает текст, а вкладку фоновая задача
   отдаст следующему запросу сразу, как он придёт (незавершённый клик при
   этом прерывается).
4. **Удержание в стриминге шима.** Раньше шим держал последние 64 символа, а
   при первом же намёке на tool-call (`<tool`, ```` ``` ````) вообще замирал
   до конца ответа — на ответах с кодом это выглядело как «всё пришло в
   конце». Теперь держится **только то, что действительно не решено**
   (недописанный тег/фенс, префикс стоп-последовательности), код-блоки идут
   обычным текстом, а распознанный вызов превращается только в блок
   `tool_use` — без дублирования JSON-текстом. Плюс `TCP_NODELAY` на SSE,
   чтобы мелкие дельты не ждали подтверждения.

Видно, где уходит время, по `--verbose` (пишет в stderr):

```bash
arena-api --claude --verbose
# [arena-api] request: 4821 chars, 12 tools, stream=True
# [arena-api] prompt 4821 chars -> open 240 ms, answer 812 chars, total 5340 ms
# [arena-api] answered in 5.41s (812 chars, stop=end_turn, engine first delta 240.3 ms)
```

`open` — от приёма запроса до готовой вкладки, `first delta` — до первого
куска ответа, `total` — до конца стрима. Если `open` большой — холодный старт
браузера/демона; если большой `first delta` — ждёт Arena (капча решается
автоматически), если растёт `total` при маленьком `first delta` — это скорость
генерации на стороне Arena.

### Сколько времени реально наше

Прежде чем обещать «в N раз быстрее», полезно посмотреть на бюджет. Профиль
тёплого демона считает три числа на каждый промпт:

```bash
arena-api --warm-profile 5
# answer.first_delta_ms = 780      ожидание первого токена (Arena «думает»)
# answer.chars = 1420              сколько символов всего
# answer.chars_per_s = 78.4        скорость генерации на стороне Arena
```

Считайте так: `total = накладные (наши) + first_delta + chars / chars_per_s`.
Всё, что после первого токена, — генерация Arena: библиотека отдаёт дельты
сразу, как только они пришли, и ускорить их нельзя, не меняя ответ. Реально
наши — запуск/переиспользование браузера, отправка промпта, удержание в
стриминге и архивация; их и убирают правки выше.

Кратный выигрыш по полному времени даёт только модель: тяжёлые модели
(`max`, `thinking`, `opus`, `pro`) «думают» 11–22 с, быстрые
(`flash-lite`, `flash`, `haiku`, `mini`) отдают ответ за ~1 с. Поэтому по
умолчанию (`fast_model=True`, `arena-api --fast-model`) выбирается быстрая
модель, а тяжёлую можно попросить явно:

```bash
arena-api --models                                  # что доступно в вашем аккаунте
arena-api --prompt "привет" --model max             # тяжёлая модель
arena-api --prompt "привет" --no-fast-model         # то же, без выбора модели
set ARENA_CLAUDE_MODEL=<быстрая-модель> && arena-claude.bat
```

### Если браузер не запускается

`Target page, context or browser has been closed` — это Chromium, который
отказался открыть **свой профиль** (`state/direct_browser_profile`), а не ошибка
Arena. Обычные причины: остался живой `chrome.exe` с этим профилем, или в
профиле остались «мёртвые» замки `SingletonLock`/`SingletonCookie` после
аварийного завершения.

Что делает библиотека сама:

1. снимает замки, владелец которых уже не жив, и повторяет запуск с тем же
   профилем (куки доверия сохраняются);
2. если профиль занят живым процессом — поднимает браузер с временным профилем
   на этот запуск (сессия всё равно подсеивается из Firefox/`cookies.json`) и
   пишет об этом;
3. если не помогло — падает с текстом, где сказано: закрыть окна браузера,
   посмотреть `--fresh-profile`, и что замки чистятся автоматически.

Начать с чистого профиля:

```bash
arena-api --fresh-profile --prompt "привет"     # удалит state/direct_browser_profile
set ARENA_CLAUDE_FRESH_PROFILE=1                # то же для arena-claude.bat
```

### Ограничения, о которых надо знать

- Шим слушает loopback и **не проверяет ключ**: любой, кто дотянется до порта,
  тратит вашу сессию. Не выставляйте `--host 0.0.0.0` без своей авторизации.
- Responses API/embeddings не эмулируются — Claude Code их не использует.
- Стриминг ответа — это стриминг Arena: время до первого токена и скорость
  генерации ограничены сервером (см. раздел про тёплый демон и `--warm-profile`).
- Эмуляция инструментов всегда добавляет инструкции в промпт: для больших
  `tools` (у Claude Code их много) промпт заметно длиннее, чем у нативного API
  (описания инструментов урезаются до 300 символов, сами схемы — нет).
- Если клиент называет модель, которой у Arena нет (Claude Code присылает свои
  `claude-sonnet-…`), шим один раз повторяет запрос моделью Arena по умолчанию,
  а не отдаёт ошибку.
